Password health

Each client's passwords to fix

The console counts each client's weak, reused, and exposed passwords. Open a count to see exactly which items to fix, by name, never by password.

Each client has its own install command, which runs our install script. Run it on the client's Windows or Linux computers from your RMM, or make a profile for your MDM on Macs, and once the extension is in the Chrome and Edge stores, people land in the right client when they sign in.

  • Installs the extension in Chrome and Edge once it's in their stores, with the server filled in

Questions

We're an internal IT team, not an MSP. Is this for us?

Yes, if you run IT for several companies, locations, or brands in one group. Each one is a client in the console, and they share one pool of seats. For a single company, see PassBundle for business.

What counts as a seat?

Each person in a client's organization who has joined. People who've been invited but haven't joined don't count, and neither do your own staff. You pay monthly for the days each seat is in use, so adding someone late in the month costs only those days. The MSP console shows each client's seats month by month and downloads them as a CSV, so you can bill each client for its own.

Which RMMs does the install command work with?

Any RMM that can run a PowerShell command as an administrator on Windows, such as NinjaOne, ConnectWise Automate, Datto RMM, and N-able, or a shell command as root on Linux. Intune and group policy work too. On Macs, macOS takes these settings only from a profile an MDM installs, so the command makes it for you to upload to yours, such as Intune, Jamf, or Kandji.

Do clients need a domain, Active Directory, or an identity provider?

No. A client's people sign in with their own email address, on any domain, and a master password, so a five-person office with a workgroup and personal email addresses works as well as a company on Entra ID. Their computers don't need to be joined to a domain. The install command runs on any Windows computer your RMM reaches. Limiting a client's install command to its email domains is optional, and so is provisioning from Entra ID.

Do you work with Microsoft Entra ID?

Yes. Provisioning from Entra ID keeps each client's people and groups in step over SCIM, and signing in with Entra is built too, each set up per client. Neither has been checked with a real Microsoft 365 tenant yet. Signing in with Entra doesn't replace the master password, which still unlocks the vault.

Can we send events to our SIEM?

Yes. Send a client's events as they happen to Microsoft Sentinel, to syslog over TLS (JSON or CEF), or to a signed webhook, from Reporting, Event streaming in its admin console. Or add your SOC's tools in the MSP console, and they get every client's events, tagged with the client, and your own staff's activity, in one feed. Events never include item names, passwords, or anything else in a vault. Each follows its service's published format, and none has been tried with Sentinel, Huntress, or Blumira themselves yet.

Can a client take its data with it?

Yes. A client's admins can export the organization's vault at any time, in a format other password managers import, and remove its MSP, which removes all of the MSP's staff at once.

Can we host it ourselves?

Yes. The server is free and open-source software under the GNU AGPLv3, and it runs on your own hardware, with SQLite or PostgreSQL. What you pay us for is the hosted service, where we run it, back it up, keep it updated, and answer when you need help.

Is there an API or PSA integration?

Not yet. Billing sync with ConnectWise, HaloPSA, and Autotask is planned, so seat counts flow into your invoices.
